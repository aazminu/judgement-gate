# Severity Implementation Plan

> Spec: `docs/superpowers/specs/2026-10-20-severity-design.md`. Read it first; this plan only orders the work.

**Goal:** a `classify:` judgement kind that labels each PR with an org-defined level, shown in the check summary, comment (when already posted), agent block and analytics, and never failing the check.

**Constraints:** baseline is 205 passing tests and a clean typecheck; keep both. Edits are small and additive (a parallel branch edits the same files). TDD: failing test, minimal code, commit.

## Tasks

1. **Types.** `JudgementVerdict.classification?`; `Judgement.kind?: "classifier"`, `Judgement.optionalAnswers?: boolean`. No behaviour; typecheck only.
2. **Classifier judgement** (`src/judgements/classifier.ts`, tests in `test/severity.test.ts`). `compileClassifier(spec)`: one `choice` question with ordered criteria; `decide` always `success`, `fired: false`; classified / unreported; case-insensitive level match returns the configured spelling; unknown level and missing answer are unreported; confidence carried through.
3. **Config parsing and validation** (`src/config.ts`, tests in `test/config.test.ts`). Dispatch on `classify`; key sets; at least 2 levels; unique (case-insensitive) short level ids; `means` required; kebab-case judgement id, built-in collision, duplicates; unknown keys; bad config falls back with a note; routing still validated separately. Routing: bare `judgement:` naming a classifier is a routing config error; `reason: severity_unreported` is accepted.
4. **Jev tolerance** (`src/jev.ts`, `test/severity.test.ts`). `optionalAnswers`: a malformed or missing answer is left out instead of throwing; one-way-door answers still required; request keys are `${id}.q`.
5. **Comment and agent block** (`src/comment.ts`, `test/agent-block.test.ts`). Extra trailing `all` parameter; `**Severity:** P1 (confidence 0.82)` line; additive `classification` array only when non-empty; schema stays 1; no PR content.
6. **Handler and analytics** (`src/handler.ts`, `src/analytics.ts`, `test/severity-handler.test.ts`, `test/analytics.test.ts`). Summary line; comment only for failing judgements, with the Severity line; check conclusion unchanged by severity; bad severity answer keeps one-way-door verdict; `blob8` level; end to end through `processPullRequest`.
7. **Docs, example, scenario.** `examples/judgement-gate.yml` (shipped example test updated), `docs/configuration.md`, `docs/agents.md`, `docs/calibration.md`, README, `scripts/scenarios.mjs`.
8. **Verify.** `npm test`, `npm run typecheck`, review the diff for PR content in the block, write the hand-over note.

## Review focus

- `aggregate()` and routing code are not edited (only `config.ts` routing validation for the classifier case).
- A block for a config with no classifier is byte-identical to before.
- Nothing from Jev's answer reaches the block except a configured level id and a number.
